# VPN v2: защищаемые объекты — этап 1 (только реестр)

Из веб-интерфейса `/vpn/protected-objects` администратор может зарегистрировать
IP /32 или IPv4 CIDR и назначить Magos-владельца. Сохраняется только
`vpn_v2_protected_objects` в БД Omnissiah со статусом `inventory_only`.

Важные инварианты:

- Ни root-helper, ни WireGuard, ни routing, ни nftables, ни agent не вызываются.
- Старые `ProtectedObject`, `AccessPolicyRule`, `FirewallRule` не используются.
- Имена уникальны; пересекающиеся объекты, VPN-пул и IP управления отвергаются.
- Только администратор может читать/создавать реестр; POST требует CSRF.
- При ошибке валидатора/БД изменение не применяется.

Реестр **не является реально работающей защитой**. Он не даёт маршрута к LAN,
не закрывает доступ к ресурсу и не обеспечивает default deny.

Следующие отдельные этапы: схема политики источник Cognitor/группа → объект →
протокол/порт → allow/deny; безопасный read-only preview маршрута туда/обратно;
транзакционный nftables Apply на выбранных Magos с журналом, ревизией,
операционным lock, откатом и проверкой фактического прохождения/блокировки
трафика. Управляющий mTLS/SSH маршрут не должен блокироваться.

Перед деплоем новой модели требуется снапшот / резервная копия БД; штатный
bootstrap создаст новую таблицу через `db.create_all()` без изменения старых.
