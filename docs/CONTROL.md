# Установка из скачанной папки на control

Стенд состоит из четырёх ВМ:

| ВМ | Назначение |
| --- | --- |
| `control` | Запуск установщика и Ansible, хранение inventory и SSH-ключа администратора |
| `omni01` | Omnissiah, веб-интерфейс и центр выдачи сертификатов |
| `magos01`, `magos02` | Агенты Magos |

`control` не включается в inventory целевых узлов и не становится VPN-шлюзом.
После установки его можно выключить; работающие компоненты от него не зависят.
Он понадобится для следующего обновления или добавления узлов.

## Скачать и запустить

1. В GitHub откройте ветку `feat/ansible-bootstrap` и выберите **Code → Download ZIP**.
   Репозиторий приватный: скачайте архив через браузер, войдя в свой аккаунт.
2. Перенесите архив или уже распакованную папку на `control`. Если архив переносите
   нераспакованным, установите `unzip` и распакуйте его.
3. Перейдите в каталог, где лежит `control-install.sh`, и запустите:

```bash
bash control-install.sh
```

Git на `control` и Git-клон для этого способа не требуются. Нужна полная папка
проекта: один скрипт без `ansible/`, `deploy/`, `src/` и `agents/` не содержит
исходников для установки. Из скачанного ZIP каталог GitHub может называться
`Omnissiah-Network-feat-ansible-bootstrap`; ориентируйтесь на наличие скрипта.

Установщик на `control`:

- Устанавливает Python, venv, pip и SSH-клиент через apt.
- Устанавливает Ansible в локальную `.ansible-venv`.
- При первом запуске спрашивает адреса `omni01`, `magos01`, `magos02` и SSH-логин.
- Сохраняет `ansible/inventory.yml`; при следующем запуске использует его снова.
- Проверяет playbook и адреса, готовит пакет исходников без Git.
- Запускает Ansible для установки компонентов на три целевые ВМ.

На `control` рекомендуется Debian 13; нужен Python 3.12+ после установки
пакетов. На целевых ВМ поддерживается Debian 13. Интернет нужен для apt/PyPI.
Если Python/SSH на control уже подготовлены, можно указать `--skip-system-packages`.

## SSH и sudo

На целевых узлах заранее должны работать SSH и учётная запись с правами sudo
(или первоначальный SSH-доступ root). Настройте доступ с control по SSH-ключу
и проверьте отпечатки ключей серверов при первом подключении.

Например, если на control ещё нет ключа, создайте его командой `ssh-keygen -t ed25519`,
а публичный ключ установите на узлы через `ssh-copy-id <логин>@<IP>`.
Пароли в inventory не записываются. При полном запуске по умолчанию Ansible
спрашивает пароль sudo целевых узлов через терминал control.

Для sudo без пароля можно запустить:

```bash
bash control-install.sh -- --become
```

Дополнительные параметры Ansible передаются после `--`, например
`--ask-become-pass` или `--private-key /путь/к/ключу`.

## Только подготовить control

```bash
bash control-install.sh --prepare-only
```

Этот режим установит инструменты, подготовит inventory и пакет без подключения
к целевым ВМ. Позже повторите обычный запуск. Для изменения адресов отредактируйте
`ansible/inventory.yml`; существующий файл установщик не перезаписывает.

При упаковке используются только runtime-исходники `src/`, `agents/`,
`templates/`, `deploy/` и необходимые корневые зависимости. `.env`, БД,
сертификаты, ключи, venv, inventory, Vault-файлы и artifacts не передаются узлам.
В Git-клоне дополнительно требуется закоммитить изменения исходников.

После установки откройте `https://<IP-omni01>:8443/login`.
Логин — `admin`, первоначальный пароль читается через sudo на omni01:

```bash
sudo cat /var/lib/omnissiah-network/admin-password
```

Публичная CA будет на control в `ansible/artifacts/ca.crt`.
Службы, диагностика и границы первого этапа описаны в [ANSIBLE.md](ANSIBLE.md).
Этот этап устанавливает управляющие компоненты; WireGuard-туннели пока не поднимаются.
