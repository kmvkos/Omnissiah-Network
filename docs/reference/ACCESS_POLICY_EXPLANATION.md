# Объяснение принципа работы правил политики доступа

## Общая концепция

Политика доступа работает по принципу **firewall rules** (правила файрвола). Вы создаете правило, которое говорит:
- **Откуда** (источник) можно обращаться
- **Куда** (назначение) можно обращаться  
- **Как** (протокол и порты)
- **На каких узлах** это правило должно применяться

## Структура правила

Каждое правило (`AccessPolicyRule`) содержит:

### 1. Источник (Source)
- **Тип**: `protected_object`, `node`, или `network`
- **Значение**: 
  - Если `protected_object` → берем сеть из защищенного объекта (например, `192.168.200.0/24`)
  - Если `node` → берем VPN IP узла (например, `172.18.16.2/32`)
  - Если `network` → используем указанную сеть напрямую

### 2. Назначение (Destination)
- Аналогично источнику, но указывает **куда** разрешен доступ

### 3. Протокол и порты
- **Протокол**: `tcp`, `udp`, `icmp`, или `any`
- **Порты**: может быть один порт (`80`), диапазон (`1000-2000`), или список (`22,80,443`)

## Что происходит при нажатии "Применить конфигурацию"

### Шаг 1: Определение узлов для применения

Система определяет, на каких узлах нужно применить правило:

1. **Omnissiah** (главный сервер) - всегда применяется локально
2. **Magos/Cognitor** - применяется через SSH или API

**Логика определения узлов:**
- Если источник - защищенный объект на Magos → правило применяется на этом Magos
- Если источник - узел Magos → правило применяется на этом Magos
- Если назначение - защищенный объект на Magos → правило применяется на этом Magos
- Если назначение - узел Magos → правило применяется на этом Magos
- **Всегда также применяется на Omnissiah** (главный сервер маршрутизирует трафик)

### Шаг 2: Генерация iptables команд

Для каждого узла генерируются команды `iptables` на основе правила:

**Пример правила:**
```
Источник: 192.168.200.0/24 (защищенная сеть за Magos)
Назначение: 172.18.16.0/24 (VPN сеть)
Протокол: tcp
Порты: 22, 80, 443
```

**Генерируемые команды iptables:**
```bash
# Для каждого порта создается отдельное правило:
iptables -A FORWARD -s 192.168.200.0/24 -d 172.18.16.0/24 -p tcp --dport 22 -j ACCEPT
iptables -A FORWARD -s 192.168.200.0/24 -d 172.18.16.0/24 -p tcp --dport 80 -j ACCEPT
iptables -A FORWARD -s 192.168.200.0/24 -d 172.18.16.0/24 -p tcp --dport 443 -j ACCEPT
```

**Где это происходит:**
- Цепочка: `FORWARD` (для межсетевого трафика)
- Действие: `ACCEPT` (разрешить прохождение пакетов)

### Шаг 3: Применение на узлах

#### На Omnissiah (локально):
```python
subprocess.run(['sudo', '-n', 'iptables'] + cmd_parts, check=True)
```
Выполняется напрямую через `subprocess`.

#### На Magos/Cognitor (через SSH):
```python
ssh = paramiko.SSHClient()
ssh.connect(ssh_ip, username='root', password=ssh_password)
ssh.exec_command(f"sudo iptables -A FORWARD ...")
```
Выполняется через SSH соединение.

### Шаг 4: Сохранение снимка конфигурации

После успешного применения сохраняется:
```json
{
    "iptables_rules": [
        ["-A", "FORWARD", "-s", "192.168.200.0/24", "-d", "172.18.16.0/24", "-p", "tcp", "--dport", "22", "-j", "ACCEPT"],
        ["-A", "FORWARD", "-s", "192.168.200.0/24", "-d", "172.18.16.0/24", "-p", "tcp", "--dport", "80", "-j", "ACCEPT"],
        ...
    ],
    "applied_on_nodes": [
        {"node_id": 1, "node_name": "Omnissiah"},
        {"node_id": 2, "node_name": "Magos-1", "ssh_ip": "10.11.11.65", ...}
    ]
}
```

Этот снимок используется для:
- **Отката** (rollback) - можно удалить правила точно так же, как они были добавлены
- **Удаления** - при удалении правила из UI, система удаляет правила с узлов по сохраненному снимку

### Шаг 5: Обновление статуса

Правило помечается как:
- `status = 'applied'`
- `applied_at = текущая дата/время`
- `applied_by = ID пользователя`

## Визуализация потока трафика

```
[192.168.200.128] (источник - защищенная сеть)
       |
       | TCP:80
       v
[Magos узел] 
       |
       | VPN туннель (WireGuard)
       v
[Omnissiah] 
       |
       | TCP:80 (iptables правило разрешает)
       v
[172.18.16.0/24] (назначение - VPN сеть)
```

## Примеры правил

### Пример 1: Разрешить доступ к веб-серверу
```
Источник: Любая сеть (any)
Назначение: 192.168.200.50/32 (защищенный объект - веб-сервер)
Протокол: tcp
Порты: 80, 443
```
**Результат:** Любой может обращаться к веб-серверу по HTTP/HTTPS

### Пример 2: Разрешить SSH только с определенной сети
```
Источник: 172.18.16.0/24 (VPN сеть)
Назначение: 192.168.200.0/24 (защищенная сеть)
Протокол: tcp
Порты: 22
```
**Результат:** SSH доступ только с VPN сети к защищенной сети

### Пример 3: Разрешить ping (ICMP)
```
Источник: 172.18.16.0/24
Назначение: 192.168.200.0/24
Протокол: icmp
Порты: (не требуется)
```
**Результат:** Разрешен ping между сетями

## Важные моменты

1. **Правила применяются на узлах, через которые проходит трафик:**
   - Если трафик идет от Magos к Omnissiah → правило на обоих узлах
   - Если трафик локальный на узле → правило только на этом узле

2. **Цепочка FORWARD:**
   - Используется для трафика, который **проходит через** узел (не для трафика, адресованного самому узлу)
   - Для трафика к самому узлу используется цепочка `INPUT`

3. **Порядок правил важен:**
   - iptables проверяет правила по порядку
   - Первое совпадающее правило применяется
   - Если правило не совпадает, проверяется следующее

4. **Удаление правил:**
   - При удалении правила из UI, система:
     1. Берет сохраненный снимок конфигурации
     2. Преобразует `-A` (добавить) в `-D` (удалить)
     3. Выполняет удаление на всех узлах, где правило было применено
