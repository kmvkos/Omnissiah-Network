## Как работают политики сейчас (из анализа кода)

### 1. Модель AccessPolicyRule

Правила политики доступа хранятся в БД:

```python
class AccessPolicyRule(db.Model):
    # Источник: ProtectedObject, узел (General), или сеть
    source_type = 'protected_object' | 'node' | 'network'
    source_id = ID объекта или узла
    source_network = IP/сеть (если source_type='network')
    
    # Назначение: ProtectedObject, узел (General), или сеть
    destination_type = 'protected_object' | 'node' | 'network'
    destination_id = ID объекта или узла
    destination_network = IP/сеть
    
    # Параметры доступа
    protocol = 'tcp' | 'udp' | 'icmp' | 'any'
    ports = '22' | '80,443' | '1000-2000'  # Порты через запятую или диапазон
    service = 'SSH' | 'HTTP' | 'HTTPS'  # Для удобства
    
    # Статус
    status = 'pending' | 'saved' | 'applied' | 'failed' | 'removed'
```

### 2. Применение правил (`api_apply_access_policy_rule`)

**Алгоритм:**
1. Определяются узлы для применения (`determine_nodes_for_rule`)
   - Если источник/назначение - защищенный объект на узле → правило на этом узле
   - Если источник/назначение - узел → правило на этом узле
   - Всегда также на Omnissiah (главный сервер маршрутизирует трафик)

2. Генерируются iptables команды (`generate_iptables_commands_for_rule`)
   - Определяется источник и назначение
   - Определяется протокол и порты
   - Генерируются команды для цепочки FORWARD (межсетевой трафик)

3. Генерируются маршруты (`generate_routes_for_rule`)
   - Если назначение - защищенный объект на Magos
   - Создается маршрут на Omnissiah: `ip route add <network> via <magos_vpn_ip> dev <omnissiah_interface>`

4. Применение на узлах:
   - **Сначала** создаются маршруты (чтобы трафик мог достичь сети)
   - **Затем** применяются iptables правила (чтобы фильтровать трафик)
   - Правила отправляются через VPN на удаленные узлы

### 3. Маршруты (`add_routes_for_protected_object`)

**Логика:**
- Если подсеть 192.168.200.0/24 привязана к Magos01
- На Omnissiah создается маршрут:
  ```
  ip route add 192.168.200.0/24 via <VPN_IP_MAGOS> dev <VPN_INTERFACE_OMNISSIAH>
  ```
- Это позволяет трафику с Omnissiah к подсети идти через VPN туннель к Magos01
- **НО** трафик будет проходить только если есть явное разрешение в AccessPolicyRule

### 4. iptables правила (`generate_iptables_commands_for_rule`)

**Текущая реализация:**
- Генерирует правила в цепочке FORWARD
- Учитывает протокол и порты
- Для TCP/UDP с портами создает правила с `--dport`
- Для ICMP создает правила с `--icmp-type echo-request`

**Проблема:**
- Не всегда создаются точные правила (только пинг, только SSH)
- Нет комментариев к правилам для идентификации

## Пример улучшенной генерации правил

### Для ICMP (ping):
```bash
iptables -A FORWARD -s <source> -d <destination> -p icmp --icmp-type echo-request -j ACCEPT -m comment --comment 'PolicyRule#123: ICMP ping'
```

### Для SSH (tcp:22):
```bash
iptables -A FORWARD -s <source> -d <destination> -p tcp --dport 22 -j ACCEPT -m comment --comment 'PolicyRule#123: tcp:22'
```

### Маршрут:
```bash
ip route add <protected_network> via <magos_vpn_ip> dev <omnissiah_interface>
```

## Важно

1. **Маршруты создаются ПЕРЕД iptables правилами** - это критично
2. **Правила применяются в порядке priority** - меньше = выше приоритет
3. **Точные правила** - только указанный протокол/порт, ничего лишнего
4. **Группировка** - для удобного управления множеством правил
5. **Интерфейс по узлам** - для удобного просмотра политик
