# Обновление Omnissiah и Magos

Все обновления запускаются с control. Только control обращается к GitHub;
на Omni и Magos копируются исходники через Ansible. Их БД, ключи, сертификаты,
пароль администратора, bootstrap и настройки VPN остаются на узлах.

## Команда

В существующем Git-клоне на control первый раз получите новый скрипт:

```bash
cd /home/fabricator/Omnissiah-Network
git pull --ff-only
bash control-update.sh
```

Следующие обновления:

```bash
cd /home/fabricator/Omnissiah-Network
bash control-update.sh
```

Скрипт требует ветку `main` и чистые исходники. Inventory и Vault исключены
из Git и не мешают обновлению. Разошедшаяся история, неопубликованные локальные
коммиты или ошибка загрузки останавливают процесс до запуска Ansible.
Повторный запуск использует существующий inventory и спрашивает пароль Vault
один раз. Для входа по ключу без Vault установщик запросит пароль sudo.
Не запускайте скрипт через sudo: используются SSH-доступ текущего пользователя
и уже подготовленные инструменты control. Обновление всей группы Magos работает
для любого числа узлов, без фиксированных magos01/magos02 в скрипте.

Если пока используете папку из ZIP, сначала перенесите inventory и Vault в
Git-клон по [CONTROL.md](CONTROL.md). Узлы переустанавливать не требуется.

## Что происходит

1. Control получает `origin/main` и допускает только fast-forward.
2. Проверяются inventory, SSH и sudo для всех целевых узлов.
3. Проверяется существующая установка; добавление новых узлов выполняется
   обычной командой `control-install.sh`, а не режимом обновления.
4. На каждом узле создаётся приватная резервная копия состояния и предыдущего
   архива исходников до изменения приложения. SQLite копируется через backup API,
   включая зафиксированные данные из WAL работающей БД.
5. Исходники обновляются. Удаляются только файлы, присутствовавшие в предыдущем
   архиве исходников и удалённые из нового. Локальные данные и venv сохраняются.
6. Ansible сверяет зависимости и конфигурации, сохраняет CA и приватные ключи,
   при необходимости продлевает сертификаты и перезапускает изменившиеся приложения.
7. Проверяются health и версия реально запущенного процесса, heartbeat
   Magos → Omni и HTTPS с сертификатом Omni → Magos.
8. Только после успешных проверок на всех узлах записывается подтверждённая версия.

Проверяются управляющие компоненты. Работа VPN этим обновлением не подтверждается
и туннели не включаются. На время перезапуска приложения возможен краткий перерыв
в управлении; обновление без простоя не реализовано.

## Версия и диагностика

Версия Omnissiah показана на странице главного узла. На каждой ВМ:

```bash
sudo cat /var/lib/omnissiah-network/deployment.json
curl -fsS http://127.0.0.1:33787/health  # Omni
curl -fsS http://127.0.0.1:5001/health   # Magos
```

`deployment.json` содержит последний успешно проверенный Git commit и хеш
пакета исходников. Health возвращает версию, загруженную при запуске процесса.
Если проверка завершилась ошибкой, установка могла обновиться частично:
не считайте старую запись deployment.json подтверждением новой версии.

```bash
sudo systemctl status omnissiah-network nginx --no-pager
sudo journalctl -u omnissiah-network -n 80 --no-pager
```

После устранения причины повторите `bash control-update.sh`.

## Резервные копии

На каждой ВМ: `/var/lib/omnissiah-network/backups/before-<хеш-новых-исходников>.tar.gz`.
Каталог доступен только root (0700), архив — 0600. Внутри находятся секреты,
включая собственную PKI узла и CA-ключ на Omni. Архивы не загружаются в GitHub
и не переносятся на control. Перед первым обновлением на конкретный хеш создаётся
один снимок; повторная попытка его сохраняет.

Снимки не содержат установленный venv и системные пакеты. Автоматический откат,
возврат схемы БД и автоматическая очистка снимков пока не реализованы. Для ручного
восстановления нужны предыдущие исходники/зависимости и согласованное состояние
БД; не распаковывайте секреты поверх работающего приложения без разбора причины.
Резервные копии занимают место на каждой ВМ; старые снимки удаляйте после проверки
новой версии и согласно своему сроку хранения.
