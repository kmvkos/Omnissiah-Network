# Policy Center — единый редактор политик Omnissiah

## Рабочий контракт

**Политика доступа** находится отдельно от VPN-топологии на
`/access-policy`. Старый `/access_policy` — перенаправление; прежние
iptables-правила оставлены только в архиве.

Создание и изменение хранят **desired** (желаемое состояние) в БД.
Сервер не должен объявлять правило действующим, пока выбранный Magos
не подтвердил полную ревизию ACL. Любое изменение проходит:
сохранение → read-only preflight → подтверждение → mTLS → root-RPC →
атомарный nft commit → проверка живой ревизии → фиксация в БД.
Удаление уже применённого правила переводит его в pending_delete,
не убирая действующее nft правило до подтверждённой транзакции.
После последнего удаления полная ACL ревизия содержит `clients=[]`.

## Data plane, действительно поддерживаемый сейчас

- Источник: Cognitor с подтверждённым ранее применением WireGuard-пира.
- Назначение: защищаемый IP/подсеть **локально за тем же Magos**.
- Протокол TCP/UDP/ICMP, отдельный порт TCP/UDP.
- Действие ACCEPT, DROP, REJECT, неявный DROP для всех неразрешённых
  сервисов **этого источника и защищаемой подсети**.
- Root управляет **только** `inet omnissiah_acl_v2`; другие nft/iptables
  цепочки, маршруты и WireGuard не модифицируются.
- Read-only preflight проверяет kernel WG peer и exact /32, route до
  ресурса, `net.ipv4.ip_forward=1`, nft syntax и предыдущую ревизию.
- Источник Cognitor должен содержать защищаемые CIDR в своих
  `AllowedIPs`. В редакторе показывается безопасная ожидаемая строка
  для клиентского `wg0.conf`; **автоматической настройки клиента нет**.
- Возврат трафика с защищаемой стороны в Cognitor должен быть
  обеспечен маршрутизацией ресурса; модуль не создаёт NAT и не
  устанавливает маршруты на стороннем сервере.
- ACCEPT здесь не гарантирует, что другая существующая base chain
  с DROP не заблокирует пакет: нужно проверять реальные пакеты.

## Cross-Magos (важно)

Сценарий `Cognitor01 → Magos03 → Magos01 → ресурс` пока **НЕ включён**.
Это намеренный отказ, а не завершённая маршрутизация: `wg0`
на source Magos не доказывает, что удалённый peer имеет в `AllowedIPs`
подсеть ресурса, что у целевого Magos есть обратный маршрут к Cognitor
и что удалённый защищаемый сервер знает обратный путь. Включать Apply
без контроля этих трёх условий нельзя. Отдельный безопасный маршрутный
транзакционный модуль требуется до заявлений о полной многошлюзовой
поддержке. Старый host-only mesh не расширяем автоматически.

## Конфигурация применения

По умолчанию **Apply выключен**. В лаборатории включается только после
изолированных тестов и снапшота:

- На Omnissiah `VPN_POLICY_APPLY_ENABLED=YES` в окружении процесса web.
- На Magos inventory `omnissiah_policy_apply_agent_enabled: true`
  (HTTP mTLS dispatcher).
- На Magos inventory `omnissiah_policy_apply_root_enabled: true`
  (root Unix RPC).
- На Magos inventory `omnissiah_policy_restore_boot_enabled: true`.
  Этим создаётся systemd restore unit, отдельная зависимость
  `wg-quick@wg0` от восстановления предыдущей ACL, и только тогда
  root получает `OMNISSIAH_POLICY_RESTORE_READY=YES`.

Без последнего флага root никогда не применяет политики.
Зависимость восстановления от запуска WG гарантирована только когда
`wg0` запускается через **systemd wg-quick@wg0**; ручной `wg-quick up`
эту гарантию обходит. Нельзя включать real Apply до проверки конкретной
процедуры reboot на стенде.

## Журнал и восстановление

В `/var/lib/omnissiah-network/vpn/` root хранит последний подтверждённый
ACL manifest, SHA-256, mutex, снимок прошлой ревизии и маркер
незавершённой транзакции. Живая nft таблица маркирована тем же
SHA-256. Status показывает расхождения после перезагрузки/вмешательства.
Apply при drift или повреждённом журнале блокируется.
При ошибке попытка восстановления предыдущей таблицы обязательна;
если откат не подтверждён, требуется ручная диагностика.

## Остающиеся ограничения

1. Требуется реальный интеграционный тест nftables + маршрутов + TCP/ICMP
   с Cognitor и ресурсом — mock CI не заменяет тестирование трафика.
2. Полноценный маршрут Cognitor через другие Magos ещё не раскатывается,
   даже если endpoint существует; нужен транзакционный WG AllowedIPs/route
   reconcile на обеих сторонах с roll-back.
3. Группы клиентов, источники-LAN за Magos, диапазоны портов и контроль
   Windows-клиентов пока не поддерживаются этим policy data plane.
4. `nftables` и `iproute2` должны быть установлены на Magos.
5. DB-статус applied — последняя подтверждённая операция, а не
   самостоятельная гарантия текущего ядра: актуальную ревизию проверяет
   root `policy-status`.

**До устранения этих ограничений не следует выдавать draft PR #34 за
полностью проверенное промышленное решение или включать ACL Apply в
нужной пользователям сети.**
