# Omnissiah Policy Center — working lab implementation (P6, Draft)

**Существующая отдельная страница** `/access-policy` является каноническим
редактором политик. Меню «VPN-сеть» предназначено для VPN-топологии, mTLS,
WireGuard и состояния клиентов. Старая `/access_policy` перенаправляет в
канонический редактор. Исторические правила iptables не переносятся
автоматически, не удаляются и доступны в legacy-архиве только для чтения.

## Доступный функционал

- Создание/редактирование/удаление *неприменённых* политик.
- Источник: Cognitor из нового реестра, в том числе черновик (только для
  планирования). Назначение: IP/подсеть из защищаемых объектов.
- Протокол TCP/UDP/ICMP, одиночный порт TCP/UDP, решения allow/deny;
  конфликт одинаковой пары источник-объект-протокол-порт запрещён.
- Live read-only preflight выбранного Magos через mTLS → root Unix socket:
  проверяется `wg0` и точный пир клиента с `AllowedIPs=/32`, доступность
  маршрута к защищаемой сети, владелец nft таблицы и синтаксис nft.
- При явном разрешении и повторной сверке ревизии корневой процесс атомарно
  обновляет **только** `table inet omnissiah_acl_v2`, FORWARD priority -30.
  Он не вызывает SSH, не меняет WireGuard, ip route, таблицы/цепочки других
  компонентов. Для каждой выбранной пары Cognitor / защищаемая сеть
  разрешённые сервисы перечислены явно, затем действует drop для прочего
  трафика Cognitor к этой *конкретной* защищаемой сети.
- В корневом состоянии хранится предыдущая ревизия; при неудаче Apply
  предпринимается автоматический откат, при неопределённом результате
  повторный Apply **запрещён**, до ручной сверки. Поддержан ручной откат
  последней ревизии по её SHA-256.

## Защитные условия

По умолчанию Apply *НЕ ДОСТУПЕН*. Нельзя просто нажать кнопку на рабочем
стенде. Перед лабораторным пилотом, после снапшота и проверки:

1. На Omnissiah: `VPN_POLICY_APPLY_ENABLED=YES` в конфигурации
   systemd/окружении приложения.
2. На Magos (явный Ansible inventory): `omnissiah_policy_apply_agent_enabled: true`.
3. На Magos root RPC (отдельный inventory opt-in):
   `omnissiah_policy_apply_root_enabled: true`.
4. На Magos должны быть `nft`, `wg`, `ip`, реальный route
   от Magos до ресурса, не пересекающийся с управлением.
5. `CognitorDraft.status=applied` в БД (наличие handshake отдельно
   проверять после установки).
6. Preview не должен сообщать ни одной ошибки; confirm name Magos и
   ожидаемая ревизия из этой страницы обязательны.

В сетевом плане различаются ресурсы «локально за Magos» (маршрут по
транзитному локальному интерфейсу) и «за другим Magos» (маршрут через
`wg0`). **Роутинг этот модуль НЕ создаёт.** Если маршрутов нет — Apply
должен быть заблокирован. Разрешение в нашем nftables-хуке не
отменяет DROP в других firewall chains.

## Чего пока нет / ограничения

- Источники-сети за Magos, группы Cognitor и порты-диапазоны ещё
  не поддерживаются в новой модели. Старый редактор с этими полями
  не следует запускать — он управляет другими маршрутами и iptables.
- Нет автоматической сверки per-rule статусов после ручного rollback:
  откат выполняется на Magos, а БД требует сверки с фактическим digest.
- Нет корректной автоматической перезагрузки ACL после reboot Magos:
  системный netfilter может потерять эту таблицу. Поэтому включать
  Apply на постоянно работающих сетях **НЕЛЬЗЯ** без отдельной
  реализации boot-restore и end-to-end тестов.
- Нет проверки фактических пакетов (allow/deny) через двухсторонний
  тестовый трафик Cognitor → ресурс. CI проверяет только код и имитацию.
- Нет журналирования отдельных применённых правил в SIEM.

**Эта PR — лабораторная реализация, НЕ production-ready.** Не
включайте три gate-флага, пока не закроем отмеченные проблемы и
не протестируем откат на изолированном стенде.
