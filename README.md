# Omnissiah Network

Система централизованного управления распределённой VPN-сетью на базе WireGuard.
Личный проект для собственной инфраструктуры и сетевого стенда.

**Текущий этап: восстановление прототипа. Подготовлено развёртывание управляющих
компонентов через Ansible; VPN-трафик и политики ещё требуют проверки на ВМ.**

## Компоненты

| Компонент | Назначение | Код |
| --- | --- | --- |
| **Omnissiah** | Веб-интерфейс, конфигурация, политики и состояние | `src/`, `templates/`, Flask + SQLAlchemy + SQLite |
| **Magos** | Управляемый Linux-узел с агентом и WireGuard | `agents/` |
| **Cognitor** | Конечный VPN-клиент | Роль узла и генерация конфигурации; отдельного приложения в репозитории нет |
| **Ansible на АРМ** | Установка и обновление компонентов, PKI, первоначальная регистрация, systemd | `ansible/`, `deploy/` |

Ansible управляет установкой. После первоначальной регистрации VPN-адреса,
ключи, соединения и политики принадлежат Omnissiah и агентам: повторный playbook
не должен перезаписывать эти настройки.
В нынешнем коде Omnissiah также может участвовать в сети WireGuard.

## Скачать папку на control и запустить

Для отдельной ВМ `control` подготовлен **[установщик из скачанной папки](docs/CONTROL.md)**.
Скачайте ZIP ветки `feat/ansible-bootstrap` через GitHub, распакуйте на control
и в каталоге проекта выполните:

```bash
bash control-install.sh
```

Он установит Ansible, спросит количество Magos, адреса узлов и SSH-пользователя,
подготовит inventory, проверит SSH и запустит раскатку. Git-клон для этого способа не нужен.
`control` управляет установкой и не входит в список VPN-узлов.

## Запуск из Git-клона через Ansible

Подготовьте одну ВМ Omnissiah и необходимое число Magos (минимум одну): Debian 13 amd64 без графики,
сеть, SSH и учётная запись с правами sudo. Python и зависимости на ВМ установит
playbook, включая первоначальную установку через `raw`.

Полная инструкция: **[docs/ANSIBLE.md](docs/ANSIBLE.md)**.

На АРМ с Linux/WSL и Python 3.12+ из корня клона:

```bash
python3 -m venv .ansible-venv
source .ansible-venv/bin/activate
python -m pip install -r ansible/requirements-control.txt
cp ansible/inventory.example.yml ansible/inventory.yml
# Укажите реальные адреса ВМ и SSH-пользователя в inventory.yml.
bash ansible/deploy.sh --ask-become-pass
```

Для Git-клона исходники должны быть закоммичены. Для скачанной папки Git
не нужен: playbook собирает runtime-пакет по содержимому исходников. Узлам
не требуется доступ к приватному GitHub-репозиторию.

После успешной установки:

- Интерфейс: `https://<IP-Omnissiah>:8443/login`.
- Логин: `admin`; первоначальный случайный пароль хранится на Omnissiah
  в `/var/lib/omnissiah-network/admin-password`, читается через sudo.
- Публичная CA для доверия браузера: `ansible/artifacts/ca.crt` на АРМ.
- Служба на каждой ВМ: `omnissiah-network.service`.
- Приватные ключи сертификатов остаются на своих узлах; CA-ключ остаётся только
  на Omnissiah. Серверный сертификат и имя/IP проверяются агентом.

Ansible проверяет heartbeat Magos → Omnissiah и HTTPS Omnissiah → Magos.
Агенты первоначально работают с `manage_wireguard: false`: туннели, маршруты,
NAT и firewall при установке не изменяются. Повторный запуск сохраняет БД,
ключи, пароль администратора и настройки VPN.

## Возможности исходного проекта

В коде имеются управление узлами и соединениями, генерация конфигураций
WireGuard, защищаемые сети, группы и политики iptables, развёртывание по SSH,
heartbeat, статистика и журнал трафика, mTLS и шифрование конфигураций.
Часть этих функций ещё требует исправлений и сквозного тестирования.

Новый путь установки использует Gunicorn и systemd, с backend только на loopback
за nginx. Старые `install.sh`, `start.sh`, `agents/run.py` сохранены для анализа
и этим playbook не вызываются. Права на сетевые изменения существующего
приложения ещё необходимо проработать отдельно.

## Структура

| Путь | Содержимое |
| --- | --- |
| `ansible/` | Inventory, роли, шаблоны systemd/nginx, команда развёртывания |
| `deploy/` | PKI, локальная регистрация, обновление bootstrap и проверки |
| `src/` | Сервер, модели, API, сетевые утилиты и WSGI entry point |
| `agents/` | Агент Magos |
| `templates/` | Веб-интерфейс |
| `tests/` | Тесты утилит, регистрации, TLS и интеграции nginx/Gunicorn |
| `docs/` | Развёртывание, состояние и справочные материалы |
| `migrate_*.py` | Существующие миграции БД |
| `mtls_utils.py` | Существующие утилиты сертификатов |
| `requirements.txt` | Зависимости сервера; системный WireGuard ставится через apt |
| `build.sh` | Архив текущего коммита Git |

Названия `NMC WG`, `nmc_*` и `omnissiah-nmc` пока встречаются в старом коде.

## Следующий рабочий результат

После установки компонентов: создать туннель между двумя Magos, проверить
handshake, добавить защищаемые подсети, разрешить и запретить выбранный трафик,
сверить желаемую и фактическую конфигурацию, перезагрузить узлы и повторить
проверки. До завершения этого сценария проект остаётся прототипом.

Проверки и ограничения: [docs/STATUS.md](docs/STATUS.md).
Справочные документы исходного проекта: [docs/reference](docs/reference/README.md).
Они сохранены как исторические материалы и могут расходиться с кодом.

## Первоначальный импорт

Основа — корневое рабочее дерево `NMC_WG/` предоставленного архива,
а не вложенные старые сборки. В Git не включены `.env`, сертификаты и приватные
ключи, базы, виртуальные окружения, IDE-настройки, кэши, логи и резервные копии.
Локальный inventory, секреты Ansible и artifacts также исключены из Git.
